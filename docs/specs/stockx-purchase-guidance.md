# StockX 购买价格参考任务规格

## 目标

新增只读任务类型 `purchase_guidance`（购买价格参考）。用户上传仅含「货号、尺码」的 Excel，任务按尺码查询 StockX 行情并给出可解释的建议出价，不创建或修改真实出价。

结果展示当前最高求购、最低卖价，以及根据逐笔成交记录计算的最近 7/30/90 天平均成交价、中位成交价和成交量。逐笔成交接口没有可用记录时，仅允许用 StockX 官方 90 天聚合数据兜底；仍然缺失的数据直接显示暂无数据，不推算或伪造数据。

## 技术栈与命令

- 后端：Java 21、Spring Boot、MyBatis Plus、EasyExcel、JUnit 5。
- 前端：React、TypeScript、Ant Design、Jest。
- 后端测试：`./build.sh test`
- 后端定向测试：`./build.sh -Dtest=<TestClass> test`
- 前端测试：`cd console && npm test -- --runInBand`
- 前端类型检查：`cd console && npm run tsc`
- 前端构建：`cd console && npm run build`

## 输入与输出契约

输入 Excel 每行：

- `货号`：必填。
- `尺码`：必填，沿用现有 US M、US W、EU 尺码匹配规则。

每条结果包含商品、尺码和 variantId，当前最高求购价、Standard/Flex 最低卖价，7/30/90 天成交统计、近期走势、成交活跃度、建议出价和建议说明。

建议规则：

1. 30 天成交不少于 3 笔且有中位价时，使用 30 天中位价作为参考成交价。
2. 否则使用 90 天中位价；只有聚合平均价时允许退化使用 90 天平均价，并在说明中明确。
3. 当前最高求购价加 `$1` 不超过参考成交价时，建议该价格；否则建议价取参考成交价，并提示当前求购价格偏高、不建议追价。
4. 没有成交参考价或当前最高求购价时不给建议价。

成交活跃度按 30 天成交量展示：不少于 10 笔为“活跃”，3～9 笔为“一般”，1～2 笔为“较少”，0 笔为“无近期成交”；30 天数据缺失时显示“数据不足”。

## 项目结构与代码风格

- `model/stockx`：成交区间和值对象、纯建议算法。
- `client/StockXClient`：StockX 响应边界解析和逐笔成交分页；异常响应必须报错，缺失行情字段保留为空。
- `task`：任务执行、进度和任务明细持久化。
- `controller`、`manager`：Excel 边界校验、快照和任务生命周期。
- `console/src/pages/task`：创建表单和通俗结果列。

金额统一使用 `BigDecimal`；第三方缺失值不转换成 0；任务只读且支持历史重跑。

## 测试策略

- 纯单元测试覆盖 30 天优先、90 天回退、超过参考价、缺少数据、活跃度和趋势。
- Client 测试覆盖第三方区间字段存在与缺失。
- Controller/Manager/Runner 测试覆盖 Excel 校验、快照、任务创建和明细保存。
- 前端测试、类型检查和构建覆盖任务入口及结果列。
- 完成后用两个真实货号运行查询，记录 StockX 实际返回的区间。

## 边界

- 始终：只读；缺失数据明确显示暂无数据；复用账号限流；每个唯一货号只查询一次。
- 先询问：自动提交建议价、修改购买任务行为、生产部署。
- 绝不：伪造 7/30 天统计；把建议价当成真实出价提交；提交密钥或未跟踪文件。

## 成功标准

- 可从任务页面上传货号和尺码并创建 `purchase_guidance` 任务。
- 每行产生一条成功或明确失败原因的任务明细，可分页查看和导出。
- 已返回的 7/30/90 天数据正确保存；缺失区间显示暂无数据。
- 建议价及说明可以从页面展示的市场价和成交价直接复算。
- 历史重跑复用原 Excel 快照。
- 后端与前端测试、类型检查和构建通过；两个真实货号完成验证。
