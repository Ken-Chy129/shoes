# eBay 定时改价任务

## 目标

新增 `ebay_price_sync` 任务。任务创建后立即执行一轮，随后每隔 `intervalHours`
小时执行一次。每轮读取 eBay 当前已发布的 offers，使用系统保存的 eBay 批量上架任务明细
按 `offerId/SKU` 关联货号和尺码，再一次性查询得物价格。

## 参数

```json
{
  "intervalHours": 6,
  "priceMultiplier": 1.1
}
```

- `intervalHours`：1~168 的整数小时。
- `priceMultiplier`：0.01~100 的正数倍率。
- 汇率使用 `PriceSwitch.EXCHANGE_RATE`（人民币元/美元）。
- 目标美元价 = 得物人民币价格 × `priceMultiplier` ÷ 汇率，四舍五入到两位小数。

## 每轮流程

1. 查询 eBay `listing_status=ACTIVE` 的 offers（分页读取）。
2. 仅保留能够通过本地 eBay 上架任务明细映射到货号和尺码的 offer。
3. 按货号批量调用得物价格接口。
4. 得物返回对应货号+EU 尺码价格时，更新 eBay offer 价格，库存保持当前数量。
5. 得物明确没有对应价格时，将 eBay offer 的可售库存改为 0，价格保持不变。
6. 单个 offer 失败只记录该商品失败，其余商品继续。

## 失败安全

- eBay 当前商品查询失败：本轮不执行任何改价或清库存。
- 得物批量查询发生技术失败：本轮不执行任何改价或清库存。
- 得物返回空集合且请求成功：视为“确认无价”，才允许库存置 0。
- 任务取消后停止下一轮，并将任务标记为已取消。
- 服务重启时恢复数据库中仍为运行中的该任务；同一生产账号最多运行一个改价任务。

## 商品范围

只处理系统通过 eBay 批量上架任务保存过映射的商品。无法从本地明细解析出
`offerId/SKU + 货号 + EU 尺码` 的手工商品会跳过并在任务属性中计数，不会盲目修改。

## 测试

- 校验参数范围和目标价计算。
- 校验得物无价时只生成库存为 0 的更新。
- 校验 eBay 或得物技术失败时不会生成任何更新。
- Mock eBay offers、更新请求和得物批量价格请求。
